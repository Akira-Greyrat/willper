# 学习中心 v2a · 问题串（关联 / 往深 / 往宽）· 设计

- 日期：2026-11-14
- 状态：待批准
- 范围：只做"每题旁边的三组可点问题"。判分闭环、错题本、计划页、体检报告都不在这份里。
- 依据：`2026-11-14-learning-center-design.md` §八 的 v2 第一项

## 一、要什么

一道题读完之后，旁边能给出三类可点的东西：

- **关联**：题库里另外几道相关的题 —— 点一下直接翻到那道题（不出对话）。
- **往深**：把这个知识点再挖一层的问题 —— 点一下发给会话里的 AI。
- **往宽**：把它和别的知识点连起来的问题 —— 点一下发给 AI。

现状：`questions.jsonl` 里每题已有 `related: { questions: [], deeper: [], broader: [] }` 字段（v1 留的空位），面板没渲染它，导入说明里也没让 AI 填。

## 二、谁生成、何时生成

**备选一：导入时一次生成（选它）**
AI 在写题库草稿时顺手把三组填上，随题目一起入库；点的时候零成本、零等待。
代价：导入时每题多花一点输出 token；导入之后新加的题没有这三组，得补。

**备选二：点的时候现生成**
面板给个「出关联网」按钮，点一次发 `/learn relate <id>`，AI 现想现写。
代价：每次点都要等一轮对话；读题时最不想等的就是这一下。**不选**为主路径。

**备选三：只生成关联，深/广留空**
成本最低，但用户当初要的就是"往深、往宽"的发散，砍掉等于没做。**不选**。

**结论**：主路径走备选一（导入时生成）；备选二降级成"补漏"——某题三组全空时，卡片上出现一个「让 AI 补这题的关联网」按钮，走现生成。两条路写同一份数据、同一个校验。

## 三、数据怎么落

`related` 结构沿用 v1，只加约束：

```json
{
  "questions": ["<另一道题的题干原文>"],
  "deeper":   ["……", "……"],
  "broader":  ["……", "……"]
}
```

- `questions` 里**不能写题号**：草稿阶段题目还没有 id（id 由 Host 写入时铸）。所以这里写**另一道题的题干**，入库时按"归一化题干"在库里解析成 id；解析不到的直接丢弃并记一条原因（不做模糊匹配）。
- `deeper` / `broader` 是自由文本问题，每条 ≤ 120 字；各最多 3 条，超出的截断。
- 三组都空是允许的（老数据就是这样），面板据此显示"补漏"按钮。

## 四、界面

题目卡下方一行三类 chip：

```
┌──────────────────────────────────────────┐
│ 题干……                                    │
│ [看参考答案] [★] [上一题] [下一题] [复习已读] │
│ 参考答案 · 要点 ①②③                       │
├──────────────────────────────────────────┤
│ 关联  另一个问题的题干…(点进那道题)          │
│ 往深  为什么闭包能记住外层变量？      [问]   │
│ 往宽  闭包和函数式编程是什么关系？    [问]   │
└──────────────────────────────────────────┘
```

- 关联 chip：点它 = 切到那道题（卡片换掉，答案收起），不产生对话。
- 深/广 chip：点它 = 走 v1 已有的 `prompt` 路由把问题发进当前会话，页面顶部出现「已发送 · 去看」（已有交互）。
- 三组全空：在 chip 行位置显示一个按钮「让 AI 补这题的关联网」→ `prompt` 发一条带题号的指令 → agent 用 `learning_question update` 写回 `related` → 面板刷新。

## 五、导入侧怎么让 AI 填

`learning_import brief` 的说明里加一段（一句话一条）：

- 每题可选给 `related`：`questions` 写**题库里另一道题的题干原文**（不是题号），`deeper` / `broader` 各 1-3 条你自己的问题；
- 只写你确信相关的；宁少勿多，空着比凑数好。

## 六、校验与防错

入库时对 `related` 做四件事，任何一条不过都**不让整题失败**，只丢那一条并记原因：

1. 类型：数组、元素是字符串；
2. 数量：各最多 3 条；
3. 长度：`deeper`/`broader` 每条 ≤ 120 字；
4. 关联解析：题干归一化后在库里找得到才转成 id，找不到丢弃，原因记为 `related_unresolved:<题干前 20 字>`。

面板与工具都走同一个 `validatePatch`（v1 已有），所以 `learning_question update` 写 `related` 时同样受约束。

## 七、验收标准

1. 导入一份带 `related` 的草稿：关联项解析成 id，深/广原样入库；一条指向不存在题干的关联被丢弃并在 `reasons` 里出现。
2. 面板：关联 chip 点击换卡；深/广 chip 点击后聊天里出现该问题。
3. 三组全空的旧题：显示「让 AI 补这题的关联网」，点了之后 AI 能写回并刷新出 chip。
4. 超过 3 条或超长的问题被截断，不报错。
5. `node --test` 全绿，`scripts/check-package.mjs` 通过。

## 八、留给 builder 的决定

- chip 的视觉细节（间距、字号、是否显示图标）。
- 关联题干太长时 chip 上截断到多少字。
- 补漏指令的具体措辞。
