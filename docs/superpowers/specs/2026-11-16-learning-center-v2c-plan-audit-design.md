# 学习中心 v2c · 阶段计划页与题库体检 · 设计

- 日期：2026-11-16
- 状态：待批准
- 范围：两个独立的小功能——把 AI 已经写好的阶段计划显示出来并能勾进度；让 AI 出一份题库体检报告并显示最近一份。
- 依据：`2026-11-14-learning-center-design.md` §八（v2 的阶段计划、v3 的体检报告）

## 一、要什么

**阶段计划页**：`meta.plan` 里的阶段（标题、该学哪些知识点、该读哪几段、要补的前置知识、一个实践项目、自查清单）在面板上按顺序显示；每个阶段可以标"未开始 / 进行中 / 已完成"。没有计划时给一个按钮请 AI 写。

**体检页**：让 AI 通读题库，按类给出结论（覆盖缺口、重复、可疑过时、跑出范围、缺答案、答案存疑），面板显示最近一份报告。

## 二、非目标

- 计划**内容**不在面板里编辑：改计划仍然走对话（`learning_plan set_plan`），面板只改状态。理由是计划的价值在"想清楚"，用表单改等于绕开思考。
- 自查清单不做逐项勾选（保持字符串数组，不迁移数据）。
- 体检报告不做结构化渲染（不做图表、不做可点击跳转），先按文本显示。
- 不做自动定时体检。

## 三、备选与选定

**报告存什么**

- 备选一：存结构化 JSON（每类一个数组），面板分块渲染。**不选**：模型写结构化长文本的格式稳定性差，一处不合 schema 就得整份重写。
- 备选二：存 markdown 文本，面板按普通文本显示（保留换行）。**选它**：显示成本最低，模型最擅长，人也直接读文件。

**计划进度怎么记**

- 备选一：阶段级状态（todo/doing/done）。**选它**：一个字段，够回答"我学到第几阶段"。
- 备选二：逐项勾选 checkpoints。**不选**：要改数据形状、要迁移；而且逐项勾选会让人误以为"勾完=学会"。

## 四、数据

不新增结构，只加一个字段：

- `meta.plan[].status`：`'todo' | 'doing' | 'done'`（AI 写计划时可以给，没给就是 `todo`），面板改它。
- 报告文件：`learning/reports/audit-<ISO 时间>.md`；`learning/reports/index.json` 存 `[{ at, file }]`，最多保留 20 条（多了删最旧的文件与索引项）。

## 五、工具与路由

新增一个 agent 工具：

| 工具 | 参数 | 作用 |
| --- | --- | --- |
| `learning_audit` | `{ action: 'brief' }` | 返回体检清单与写作要求（每类 0-5 条、必须点出题号或知识点、结尾给"下一步三件事"），不改库 |
| `learning_audit` | `{ action: 'write', markdown }` | 把报告写到 `reports/audit-<时间>.md` 并更新 `index.json`；返回 `{ at, file }` |

路由新增两个 op：

| op | 参数 | 返回 |
| --- | --- | --- |
| `setStageStatus` | `{ stageId, status }` | `{ ok, plan }`——只改 `meta.plan` 里那一个阶段；未知阶段 400 |
| `report` | `{}` | `{ at, markdown } \| null`——最近一份；文件被删时返回 null 而不是报错 |

## 六、界面

页签变成六个：学习 / 题库 / 错题 / 收藏 / 计划 / 体检。

**计划页**

```
┌ 阶段 2 / 4 · 进行中 ─────────────────────────┐
│ 打牢作用域                                     │
│ [未开始][进行中][已完成]  ← 当前状态高亮         │
│ 知识点：词法作用域 · 闭包                        │
│ 该读：materials/bank.md 第 3-5 节               │
│ 要补：动态作用域（对比着看）                     │
│ 实践项目：写一个计数器工厂，说明闭包保住了什么      │
│ 自查：能不看书讲清闭包与作用域的关系               │
└──────────────────────────────────────────────┘
```

- 空态：一段说明 + 「让 AI 写阶段计划」按钮（`prompt` 发一条指令，AI 用已有的 `learning_plan set_plan` 写回，用户点刷新看到）。

**体检页**

- 有报告：显示 `at` 时间 + 报告正文（`white-space: pre-wrap`）。
- 没有报告：说明 + 「让 AI 体检题库」按钮（`prompt`）。
- 无论有没有报告，顶部都有「重新体检」，点了同上。

## 七、验收标准

1. 计划页按顺序显示 `meta.plan` 的所有阶段，知识点 id 换成树里的标题；没有计划时显示空态与按钮。
2. 点某个阶段的状态，刷新后仍是新状态；`meta.plan` 里只有那个阶段变了。
3. 体检页没有报告时显示空态；点「让 AI 体检题库」后 AI 调 `learning_audit write`，刷新能看到报告正文与时间。
4. 再体检一次会产生新文件，面板显示最新一份，`index.json` 里最少两份。
5. `reports/` 里超过 20 份时最旧的被删。
6. `node --test` 全绿，`scripts/check-package.mjs` 通过。

## 八、风险

- **报告写得泛泛**：brief 里要求"点名题号或知识点、每类最多 5 条、结尾三件事"，并在工具说明里重复一次。
- **体检是长回合**：AI 要读状态与题库，可能几十秒；面板只发指令，不阻塞。

## 九、留给 builder 的决定

- 计划页与体检页的具体间距与分组样式。
- 报告正文是否按行加前缀（例如把 `##` 显示成加粗标题的极简处理）——建议先纯文本。
- 阶段状态的切换是三个按钮还是下拉。
